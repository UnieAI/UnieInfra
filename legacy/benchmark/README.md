# UnieInfra Benchmark

Automated, reproducible serving benchmark that measures **TTFT, TPOT, throughput,
and RPS** across a **concurrency sweep (1, 16, 32, 64, 128, 256)** using
`vllm bench serve` (the InferenceMAX-standard client), against any
OpenAI-compatible engine — UnieInfra, vLLM, SGLang, LMDeploy — for apples-to-apples
comparison. **All raw results are saved.**

## Layout
```
benchmark/
├── run_sweep.sh          # the harness: concurrency sweep -> raw + summary
├── summarize.py          # raw JSONs -> summary.csv (saves every scalar metric)
├── bench_and_profile.sh  # ONE-COMMAND loop: launch+sweep -> profile -> trajectory -> delta
├── trajectory.py         # results/**/summary.csv -> results/TRAJECTORY.md (+ .csv)
├── recut_aggregate.py    # N repeat runs -> median + min/max spread + WIN/TIE/LOSE verdict
├── profile_hot_decode.py # light steady-state decode profile (torch.profiler / nsys)
├── configs/              # <label>.env knobs for bench_and_profile.sh (see example.env)
├── launch/               # start each engine's OpenAI server
│   ├── launch_unieinfra.sh
│   └── launch_vllm.sh
├── scripts/              # offline smoke/throughput tests + sm_120 env
│   ├── sm120_env.sh
│   ├── m1_forward_smoke.py       # correctness (single request)
│   ├── m1_concurrency_smoke.py   # offline aggregate throughput
│   └── bench_vllm.py             # offline vLLM comparison
└── results/
    ├── TRAJECTORY.md / trajectory.csv   # generated by trajectory.py -- don't hand-edit
    └── <engine>/<label-or-timestamp>/
        ├── env.txt       # GPU, versions, sweep params
        ├── launch.json   # card/count/serve params, copied from launch/<engine>.launch.json
        ├── raw/
        │   ├── c<N>.json         # full vllm-bench result per concurrency
        │   └── c<N>.stdout.log   # full client stdout
        └── summary.csv   # one row per concurrency, ALL metrics
```

## Run a sweep
1. **Start a server** for the engine under test (a free GPU):
   ```bash
   MODEL=/workspace/models/Qwen/Qwen3-8B GPU=1 PORT=8000 benchmark/launch/launch_unieinfra.sh &
   # or: MODEL=/workspace/models/Qwen/Qwen3-8B GPU=1 PORT=8001 benchmark/launch/launch_vllm.sh &
   ```
2. **Sweep** it (the client can run anywhere that can reach the port; it needs a
   python with `vllm` installed for `vllm bench`):
   ```bash
   ENGINE=unieinfra BASE_URL=http://127.0.0.1:8000 MODEL=bench-model \
   VLLM_PY=/home/ubuntu/vllm-bench-venv/bin/python \
   benchmark/run_sweep.sh
   ```
3. Compare `results/*/*/summary.csv` across engines.

## Knobs (env vars)
`CONCURRENCIES` (default `1 16 32 64 128 256`), `ILEN`/`OLEN` (random input/output
len), `PROMPTS_PER_CONC` (num_prompts = concurrency × this), `ENDPOINT`
(`/v1/completions`). Raw is never overwritten — each run gets its own timestamp dir.

## Metrics
`request_throughput` = **RPS** (req/s) · `output_throughput` = decode **tok/s** ·
`mean/p99_ttft_ms` = **TTFT** · `mean/p99_tpot_ms` = **TPOT** (per-output-token
latency) · `mean/p99_e2el_ms` = end-to-end. The summary CSV keeps *every* scalar
the client reports; per-request arrays live in `raw/`.

## Continuous loop: change → run → profile → know what to fix next

One command drives the whole cycle for a saved run label:

```bash
benchmark/bench_and_profile.sh <label> [engine]     # engine: unieinfra (default) | vllm
```

It (a) launches the engine and runs the aligned sweep into
`results/<engine>/<label>/` (same hygiene as `run_sweep.sh`: fixed
`PROMPTS_PER_CONC`/`WARMUPS`/`SEED`, `FLUSH=1` between concurrency levels,
prefix cache ON), (b) runs a light steady-state decode profile at batch-1 and
batch-128 into `profiles/<label>/`, (c) refreshes `results/TRAJECTORY.md`
over *every* saved run, and (d) prints this label's delta vs the previous
label and vs a fixed baseline (default `clean`), flagging a regression if any
concurrency got worse.

**1. Add a config for the change you're testing.** Drop the env knobs into
`configs/<label>.env` (copy `configs/example.env`, which documents every knob
it understands: `MODEL`/`GPU`/`PORT`; the `launch_unieinfra.sh` knobs
`DTYPE`/`ATTN`/`MAX_NUM_SEQS`/`MAX_CGRAPH`/`DISABLE_RADIX`; the `run_sweep.sh`
hygiene knobs; and `BASELINE`/`PROFILE`/`CONTAINER` for the wrapper itself).
`bench_and_profile.sh` only passes environment through — it doesn't hardcode
the launch scripts' flags — so any new knob `launch_unieinfra.sh` grows later
already works here once it's wired there.

**2. Run it.**
```bash
benchmark/bench_and_profile.sh my_change
```

**3. Read `results/TRAJECTORY.md`.** Three tables, regenerated from every
`results/**/summary.csv` on disk (ragged runs — e.g. a label that only swept
a subset of concurrencies — show `-` for missing cells, never crash):
1. **Trajectory** — every run × concurrency, so a win or regression across
   the whole history of changes is visible at a glance.
2. **Delta vs baseline** — same shape, as a % change, so you don't do the
   mental math.
3. **UnieInfra vs vLLM vs SGLang** — side-by-side at each concurrency with a
   winner marker, because the bar is "beat them", not "beat yesterday" (see
   `benchmark/results/vllm/clean/` and `.../sglang/clean/`).

Pick the metric with `benchmark/trajectory.py --metric mean_ttft_ms` or
`--metric mean_tpot_ms` (default `output_throughput`); `--help` for the rest.

**4. Read the profile hint.** `profiles/<label>/bs1_hotkernels.md` and
`bs128_hotkernels.md` each have a top-N kernel table, a category breakdown,
and a one-line "likely lever" heuristic (e.g. *"gemv-dominated → DRAM-
bandwidth bound → try weight quantization or a bigger batch"*). This is a
kernel time-share heuristic, not a hardware-counter roofline — confirm with
`ncu` before spending real optimization effort, once HW counters are
unlocked (they're `RmProfilingAdminOnly`-blocked in this environment today,
which is why the profiler defaults to `torch.profiler` via the server's own
`/start_profile`/`/stop_profile` endpoints, with an `nsys`-timeline mode
as the other always-available fallback — see `profile_hot_decode.py --help`).

**Validate without touching a GPU.**
```bash
benchmark/bench_and_profile.sh <any-existing-label> --dry-run   # steps (c)+(d) only, on existing data
benchmark/trajectory.py                                          # just the trajectory view
```

## Repeats: is the delta bigger than the noise?

A single sweep per engine cannot tell a real win from box drift. When a number
has to *decide* something, run the same sweep **N>=3 times per engine, rotating
engines between repeats** (unieinfra → vllm → unieinfra → vllm, not all of one
engine then all of the other) so slow drift hits every engine equally, and label
the runs `<prefix>_<engine>_r1|r2|r3`. Then:

```bash
benchmark/recut_aggregate.py recut_a_bf16
```

It prints, per metric, a `median [min-max]` cell for every (engine,
concurrency) plus a **WIN / TIE / LOSE** verdict — where **TIE means the two
engines' observed ranges overlap**, i.e. the delta is not separable from
run-to-run noise. A delta smaller than the spread is not a result.

Worked example: `benchmark/results/RECUT_A_BF16_AGGREGATE.md` (E35 — Qwen3-8B
bf16, UnieInfra vs vLLM, N=3 on an otherwise-idle GPU; spreads came out
<0.2%, so every reported delta was real).

## Hygiene rules

These are enforced by `run_sweep.sh` (and therefore by
`bench_and_profile.sh`, which wraps it) — don't work around them when adding
a new config:
- **Fixed `PROMPTS_PER_CONC`/`WARMUPS`/`SEED`** across runs you're comparing
  → identical prompt set every run; don't vary these mid-comparison.
- **`FLUSH=1`** between concurrency levels so one level's cache state can't
  ride into the next.
- **Prefix cache stays ON.** It's a real, production feature; isolation
  between levels comes from the flush, not from disabling it.
- **Back-to-back, same box.** Don't compare a run from last week against one
  from today on a different GPU.
- **Best-vs-best.** Don't handicap vLLM/SGLang to make UnieInfra look
  better — only tune UnieInfra's own config (strong defaults, not
  hand-tuning against a fixed benchmark).
