KV 快取放在哪裡：GPU、記憶體、SSD

一句話：GPU 放不下的對話記憶（KV），先搬到主機記憶體，再存到 SSD。下次同樣開頭的請求進來，從那裡讀回來，不用重算。

我們的做法（MI350P ×4）

4 張卡的 KV 內容其實一模一樣（DeepSeek V4.1 的特性），所以 SSD 只存一份給大家讀（PR #51），空間省 4 倍。記憶體這層目前還是每張卡各存一份，是下一個要改的地方。

跟 Hibana 比

Hibana 跑在 GB10（CPU 和 GPU 共用同一塊記憶體），所以它沒有 ② 這層：GPU 直接存到 SSD。我們是獨立顯卡，顯存和主機記憶體是分開的，才多一層。

UnieInfra（MI350P）Hibana（GB10）
層數GPU → RAM → SSDGPU → SSD （無 RAM 層）
什麼時候寫 SSD從 GPU 退出時（eager 模式）退出時，且前綴 ≥ 4096 token；關機時全寫
檔案格式一次寫一個 segment 檔，CRC 檢查256 token 一個檔，CRC，寫 .tmp 再 rename （類似）
讀寫方式寫用 O_DIRECT，讀走 page cache讀寫都 O_DIRECT，2×256 MiB 雙緩衝
重開機掃目錄重建索引 （相同）掃目錄，版本不符就刪
多卡（TP）4 卡內容相同 → 只存一份每卡存自己那份
實測24k：0.82 s → 0.08 s258k：353 s → 0.77 s

可以從 Hibana 學的

  • 關機時把 GPU 上所有前綴寫到 SSD，重開後馬上有快取。
  • 太短的前綴（< 4096 token）不寫 SSD，省寫入量。
  • 快取 key 加上模型版本、權重、格式的雜湊，換模型時舊檔自動作廢。
  • GB10 版本（等機器中）可以照它的做法：拿掉 RAM 層，GPU 直接寫 SSD。
