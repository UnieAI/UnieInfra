UnieInfra KV 分層快取：HBM → RAM → SSD

MI350P ×4、DeepSeek V4.1 TP4。GPU 放不下的 KV 先退到主機 RAM（L2），再寫到 NVMe 檔案（L3）。重啟後仍可從 L3 讀回，不用重算 prefill。對應 PR #49（檔案 L3）、#50（segment 檔）、#51（TP 去重）。

寫入 一段 prompt 怎麼進 SSD

  1. prefill 完，KV 在 GPU 的 radix 樹上。
  2. GPU 要空間時，頁面退到同一 rank 的 L2 RAM。
  3. 寫入策略 eager：同時排進 L3 寫入佇列（預設 reuse 只寫被重複用過的前綴）。
  4. DSV4.1 的 KV 在 4 個 TP rank 上完全一樣（27,452 個物件比對全同），所以只有 rank 0 寫檔，其他 rank 只登記索引。
  5. 一次 put 寫成一個 segment 檔，O_DIRECT 不汙染 page cache。

讀回 新請求命中前綴

  1. 排程器比對前綴：GPU → L2 → L3 依序找最長命中。
  2. L3 命中先 prefetch 到 L2（16 個 IO thread，按 slice 分派）。
  3. 4 個 rank 讀同一個檔，第一次之後走 page cache。
  4. L2 → GPU 逐層搬，每層用 fence 等該層到位再算（上游 #2812 的修補）。
  5. 只 prefill 沒命中的尾巴。

還沒做的
